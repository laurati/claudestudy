Disciplina 07

Desenvolvimento de aplicações com IA

Chega de brincar com a IA: é hora de colocá-la para funcionar em aplicações de verdade — tanto como ferramenta de construção (backend Nest.js, frontend Next.js, design system com Figma) quanto como parte da aplicação (SDKs, LangChain, RAG).

Ao finalizar esta disciplina você será capaz de:

  • Conectar modelos de IA nas suas aplicações com controle total
  • Criar fluxos reutilizáveis e organizados para trabalhar com IA
  • Enriquecer as respostas da IA com dados do seu próprio sistema
  • Automatizar extrações e análises em grandes volumes de texto
  • Aumentar a precisão das respostas com menos risco de alucinação

IA dentro da aplicação: SDKs, LangChain e RAG

Antes do conteúdo programático, a base prática para os objetivos acima: como uma aplicação chama um modelo, dá ferramentas a ele, extrai dados estruturados e usa RAG.

Tool use: dando acesso aos dados do seu sistema

Com tool use você descreve funções (nome, descrição, JSON Schema); o modelo decide chamá-las; sua aplicação executa e devolve o resultado.

Exemplo: loop de ferramentas em Python

import json, anthropic
client = anthropic.Anthropic()

tools = [{
    "name": "buscar_pedido",
    "description": "Retorna status, itens e data de um pedido pelo ID.",
    "input_schema": {
        "type": "object",
        "properties": {"pedido_id": {"type": "string", "description": "Ex.: PED-123"}},
        "required": ["pedido_id"],
    },
}]

def executar(nome, entrada):
    if nome == "buscar_pedido":
        return db.pedidos.get(entrada["pedido_id"])   # sua lógica real

msgs = [{"role": "user", "content": "Meu pedido PED-123 já foi enviado?"}]
while True:
    resp = client.messages.create(model="claude-opus-5-5", max_tokens=2000, tools=tools, messages=msgs)
    if resp.stop_reason != "tool_use":
        break
    msgs.append({"role": "assistant", "content": resp.content})
    msgs.append({"role": "user", "content": [
        {"type": "tool_result", "tool_use_id": b.id, "content": json.dumps(executar(b.name, b.input))}
        for b in resp.content if b.type == "tool_use"
    ]})

print(next(b.text for b in resp.content if b.type == "text"))

Extração estruturada em grandes volumes

Para extrair campos de milhares de documentos (contratos, e-mails, notas), combine structured outputs (garante o JSON) com a Batch API (mais barato) e suporte a PDF.

LangChain e RAG

LangChain oferece abstrações para prompts, modelos, loaders de documentos, splitters, vector stores e retrievers — útil para montar pipelines RAG rapidamente. Conceitos de RAG: Disciplina 01 e Disciplina 03.

Exemplo: RAG mínimo com LangChain

# pip install langchain-anthropic langchain-community langchain-text-splitters langchain-huggingface faiss-cpu
from langchain_anthropic import ChatAnthropic
from langchain_community.document_loaders import DirectoryLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

docs = DirectoryLoader("docs/ajuda", glob="**/*.md").load()
chunks = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100).split_documents(docs)
store = FAISS.from_documents(chunks, HuggingFaceEmbeddings(model_name="sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"))

pergunta = "Como emitir a segunda via do boleto?"
trechos = store.similarity_search(pergunta, k=4)
contexto = "\n\n".join(f"[{i}] {d.page_content}" for i, d in enumerate(trechos))

llm = ChatAnthropic(model="claude-opus-5-5", max_tokens=1000)
resposta = llm.invoke(
    f"Responda só com base nos trechos, citando [n]. Se não houver a informação, diga que não sabe.\n\n"
    f"<trechos>\n{contexto}\n</trechos>\n\nPergunta: {pergunta}"
)
print(resposta.content)

Fundamentos do Desenvolvimento com IA

Ferramentas, IDEs e workflows de desenvolvimento com IA

Recapitulando (Disciplinas 05 e 06): assistentes na IDE (Cursor, Copilot, Windsurf), agentes de terminal (Claude Code), agentes na nuvem que abrem PRs, servidores MCP e ferramentas de design (Figma). O workflow importa mais que a ferramenta.

Pilares do desenvolvimento moderno com IA

  1. Contexto: documentação e regras que o agente lê.
  2. Especificação: o que construir, com critérios verificáveis.
  3. Verificação: testes, tipos, lint, E2E.
  4. Iteração em passos pequenos com commits frequentes.
  5. Reuso de conhecimento: skills, comandos, templates.

Introdução ao Spec Driven Development e paralelização

Specs como fonte de verdade e tasks independentes executadas em paralelo por subagentes — detalhado na Disciplina 06.

Documentação e artefatos que guiam a IA

PRD, specs, ADRs, OpenAPI, design tokens, guidelines de testes, CLAUDE.md/AGENTS.md. Cada artefato responde a uma pergunta que o agente faria.

Preparando o Ambiente para a IA

Arquivos de inicialização e contexto do agente

CLAUDE.md (Claude Code), AGENTS.md (padrão aberto), .cursor/rules/, .github/copilot-instructions.md. Um truque comum: manter o conteúdo em AGENTS.md e fazer o CLAUDE.md importá-lo (o Claude Code suporta importar arquivos com @caminho).

Testabilidade, convenções e políticas do projeto

Um projeto "amigável à IA" é, antes de tudo, um projeto testável: rodar um teste específico em segundos, ambiente local reproduzível (Docker), dados de seed, mensagens de erro claras. Políticas: o que o agente pode fazer sozinho (rodar testes, editar src/) e o que exige humano (push, migração em produção, mudar dependências).

Evolução e otimização de projetos existentes

Comece pelo "onboarding" do agente, gere o arquivo de contexto, adicione testes de caracterização nas áreas que serão alteradas, e evolua o harness a cada erro recorrente do agente.

Skills: Reutilizando Conhecimento com a IA

Que problemas as Skills resolvem no dia a dia

  • Repetir as mesmas instruções em toda sessão ("nosso padrão de migração é…").
  • Contexto inchado: colocar tudo no CLAUDE.md custa tokens sempre.
  • Conhecimento que exige ferramentas (scripts, templates), não só texto.
  • Compartilhar boas práticas entre projetos e pessoas.

Skills oficiais da Anthropic e estruturação (frontmatter)

A Anthropic publica skills de exemplo e de documentos em github.com/anthropics/skills. A estrutura mínima:

---
name: typeorm-migrations          # identificador (minúsculas, hífens)
description: Cria e revisa migrações TypeORM seguindo os padrões do projeto. Use ao alterar entidades ou schema do banco.
---
# Instruções
...

A description é o que o modelo usa para decidir quando carregar a skill — escreva o que faz e quando usar.

Progressive disclosure e detalhes condicionais

Nível 1 name + description → sempre no contexto (poucas dezenas de tokens) Nível 2 corpo do SKILL.md → carregado quando a skill é relevante Nível 3 arquivos referenciados → lidos só se necessários (reference/postgres.md, reference/mysql.md, scripts/*.py)

Exemplo de detalhe condicional no SKILL.md: "Se o banco for PostgreSQL, leia reference/postgres.md; se for MySQL, reference/mysql.md." Assim só o necessário entra no contexto.

Criação de Skills próprias e integração com servidores MCP

MCP dá capacidades (acesso ao banco, ao Figma); skills dão know-how (como usar essas capacidades do jeito do seu time). Ex.: uma skill db-investigation que ensina a consultar o banco via MCP Postgres com queries somente leitura e limites.

Iniciando Projetos do Zero com IA

Abordagem para projetos novos (greenfield)

  1. PRD de alto nível + escolha de stack registrada em ADRs.
  2. Guidelines e CLAUDE.md antes do código.
  3. Esqueleto que roda de ponta a ponta (walking skeleton) com CI e testes.
  4. Features em fatias verticais pequenas.

Indo além do "Hello World"

O "Hello World" gerado por IA é fácil; o difícil é a fundação de produção: autenticação, configuração por ambiente, logs estruturados, tratamento de erros padronizado, migrações, health checks, Docker, CI, testes de cada camada. Peça isso explicitamente no bootstrap.

Testes Automatizados na Era da IA

Definição e categorização de testes

TipoEscopoVelocidadeExemplo
UnitárioUma função/classe isoladamsOrder.canCancel()

ContratoAcordo entre consumidor e provedor de APIsPact, validação de OpenAPI

Cobertura de código e o valor real de cada teste

Cobertura mostra o que não foi testado, mas não garante que o que foi executado foi verificado. IA consegue facilmente gerar 90% de cobertura com asserts fracos. Meça valor com mutation testing e pergunte: "se eu introduzir um bug aqui, algum teste falha?"

Caminho feliz, caminho triste e edge cases

  • Feliz: entrada válida, fluxo esperado.
  • Triste: entradas inválidas, dependências falhando, permissões negadas.
  • Edge cases: limites (0, 1, máximo), vazios, unicode, fuso horário, concorrência, idempotência.

Diretrizes de teste com criação e auditoria assistidas por IA

# docs/TESTING.md (trecho)
- Um teste verifica UM comportamento; nome: "deve <resultado> quando <condição>"
- Não mockar o que é nosso dentro do mesmo módulo; mockar apenas fronteiras (HTTP, fila, LLM)
- Proibido: asserts só de "não lançou exceção"; snapshots gigantes; sleep()
- Todo bug corrigido ganha um teste de regressão

Prompt de auditoria:
"Audite os testes em src/orders/**. Para cada teste, diga se ele detectaria um bug
real (dê um exemplo de mutação que ele pegaria) ou se é fraco. Sugira melhorias."

Testes de ponta a ponta (E2E) de navegação

Playwright com seletores por role/label (resistentes a mudanças de layout), dados de teste isolados, e execução no CI. O agente pode usar o Playwright MCP para explorar a aplicação e então escrever o teste.

TDD (Test Driven Development) com IA

TDD é especialmente poderoso com agentes: o teste é a especificação executável e o critério de pronto. Ciclo: Red (você/IA escreve o teste, confirma que falha) → Green (IA implementa o mínimo) → Refactor (IA melhora com os testes verdes).

Exemplo: instruções de TDD para o agente

Vamos fazer TDD para a regra de cancelamento.
1. Escreva SOMENTE os testes em order.spec.ts para os critérios RF-01..RF-03. Rode e confirme que falham.
2. Faça commit dos testes ("test: cancelamento").
3. Implemente o mínimo para passar. NÃO altere os testes.
4. Refatore mantendo verde. Commit.

Backend com Nest.js e ambiente com Docker

Exemplo: docker-compose para desenvolvimento

services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: app
    ports: ["5432:5432"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
  api:
    build: ./apps/api
    env_file: .env
    ports: ["3000:3000"]
    depends_on:
      db: { condition: service_healthy }
// apps/api/src/orders/http/orders.controller.ts
@Controller("orders")
export class OrdersController {
  constructor(private readonly cancelOrder: CancelOrderUseCase) {}

  @Post(":id/cancel")
  @ApiResponse({ status: 200, type: OrderDto })
  @ApiResponse({ status: 409, description: "Pedido não pode ser cancelado" })
  async cancel(@Param("id") id: string, @Body() body: CancelOrderDto) {
    const result = await this.cancelOrder.execute(id, body.reason);
    if (result.isErr()) throw new ConflictException(result.error.message);
    return OrderDto.from(result.value);
  }
}

Configuração de contexto e regras para a IA

CLAUDE.md na raiz (visão do monorepo, comandos) + CLAUDE.md em apps/api (padrões Nest: um módulo por domínio, DTOs com class-validator, use cases sem dependência do Nest, repositórios via interface).

Curadoria de Skills de boas práticas (Nest.js e TypeORM)

Em vez de escrever do zero, faça curadoria: parta de skills públicas/da comunidade, revise (podem conter más práticas ou até instruções maliciosas), adapte às suas convenções e versione no repositório. Exemplos: nestjs-module (como criar módulo, provider, testes), typeorm-migrations (nunca usar synchronize: true; migrações reversíveis; índices concorrentes).

Integração de servidores MCP (Context7 e PostgreSQL)

  • Context7: injeta documentação atualizada e específica de versão das bibliotecas (Nest, TypeORM, Next) — reduz alucinação de APIs antigas.
  • PostgreSQL MCP: o agente consulta o schema e dados reais (use usuário somente leitura e banco de dev).
claude mcp add --transport http context7 https://mcp.context7.com/mcp
claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres postgresql://readonly:pw@localhost:5432/app

Workflow: Pesquisar, Planejar e Implementar

Ciclo de pesquisa, planejamento e implementação com IA

  1. Pesquisar: o agente lê código, docs (Context7) e schema (MCP) e escreve research.md com o que encontrou.
  2. Planejar: a partir da pesquisa, gera plan.md dividido em fases, com arquivos e testes de cada fase.
  3. Implementar: fase por fase, rodando gates ao final de cada uma.

Geração e revisão de planos de implementação por fase

Revise o plano como revisaria um PR — é muito mais barato corrigir um plano do que código. Use o plan mode do Claude Code (o agente pesquisa e propõe sem editar arquivos).

Gestão da janela de contexto

  • Uma sessão por fase; inicie limpa com /clear e aponte para plan.md.
  • /compact quando a sessão ficar longa, com instruções do que preservar.
  • Subagentes para pesquisas extensas.
  • Evite colar logs/arquivos gigantes; prefira que o agente leia trechos.

Simplificação de código e commits assistidos por IA

Após a implementação, peça uma passada de simplificação ("remova abstrações desnecessárias, código morto e duplicação, sem mudar comportamento") e gere commits pequenos com mensagens convencionais (feat:, fix:, refactor:) descrevendo o porquê.

Design System com IA e Figma

Front-end na era da IA e ferramentas de design

Gerar telas virou trivial; manter consistência visual não. O design system (tokens + componentes + regras) é o "contexto" que impede a IA de criar uma interface diferente a cada tela.

Integração com o Figma via MCP

O servidor MCP do Figma permite que o agente leia frames, componentes, variáveis e estilos de um arquivo de design e gere código fiel a ele (em vez de "adivinhar" a partir de um screenshot).

Sincronização de design tokens entre Figma e código

Figma Variables / Tokens ──export JSON──► tokens.json ──Style Dictionary──► CSS vars / tailwind config ▲ │ └──────────── auditoria (MCP + IA): divergências entre design e código ◄──────┘

Exemplo: tokens como variáveis CSS (padrão shadcn/Tailwind)

Auditoria e aplicação automatizada de tokens

Audite src/components/**: encontre cores hex/rgb, tamanhos em px e sombras
que não usam os tokens definidos em src/styles/tokens.css.
Gere uma tabela (arquivo, linha, valor, token sugerido) e aplique as
substituições óbvias; liste as ambíguas para decisão do design.

Complemente com regras de lint (ex.: plugin que proíbe cores arbitrárias no Tailwind) — enforcement mecânico.

Uso de shadcn e regras do design system

shadcn/ui não é uma dependência fechada: os componentes são copiados para o seu projeto (Radix + Tailwind), então você e a IA podem adaptá-los. Isso o torna muito "amigável a agentes".

npx shadcn@latest init
npx shadcn@latest add button dialog form table

Regras típicas no contexto: "use componentes de @/components/ui; nunca crie botão do zero; variantes via cva; ícones apenas de lucide-react".

Fundação de IA para projetos Next.js

CLAUDE.md do app web: app router vs pages, server vs client components, onde ficam fetchers, padrão de formulários (react-hook-form + zod), estados de loading/erro (loading.tsx, error.tsx), regras do design system, comandos de teste. Use Context7 para a versão exata do Next.

Estratégias de teste no front-end (E2E e mocks de API)

  • Componentes: Testing Library (comportamento, não implementação).
  • Mocks de API: MSW (Mock Service Worker) intercepta requisições — gere os handlers a partir do OpenAPI para manter o contrato.
  • E2E: Playwright contra o backend real em ambiente de teste, poucos fluxos críticos.

Exemplo: mock com MSW

import { http, HttpResponse } from "msw";

export const handlers = [
  http.post("/api/orders/:id/cancel", ({ params }) =>
    params.id === "42"
      ? HttpResponse.json({ id: "42", status: "CANCELADO" })
      : HttpResponse.json({ message: "Pedido não pode ser cancelado" }, { status: 409 })
  ),
];

Planejamento de telas e implementação por fase

  1. Inventário de telas e estados (vazio, carregando, erro, sucesso) a partir do PRD e do Figma.
  2. Fase 1: layout e navegação com dados mockados (MSW).
  3. Fase 2: integração com a API real.
  4. Fase 3: E2E dos fluxos críticos, acessibilidade, responsividade.

Exercícios e quiz

Projeto — mini e-commerce assistido por IA

Construa backend (Nest + Postgres + Docker) e frontend (Next + shadcn) para "pedidos com cancelamento", seguindo: PRD → spec → plano por fases → TDD → E2E. Adicione um assistente de suporte com tool use (buscar_pedido, cancelar_pedido com confirmação humana) e RAG sobre as FAQs.

1. Qual a função da description no frontmatter de uma skill?
Ela fica sempre no contexto e é o gatilho do progressive disclosure.
2. No tool use, quem executa a função buscar_pedido?
O modelo só pede a chamada (tool_use); a execução e a segurança ficam com você.
3. Por que o Context7 MCP ajuda a reduzir erros do agente?
Evita APIs inventadas ou de versões antigas presentes no treinamento.
