Protocolos de comunicação: MCP e A2A

Não adianta ter agente, modelo e ferramenta se eles não se integram. MCP conecta a IA a dados e ferramentas; A2A conecta agentes a outros agentes — mesmo de tecnologias diferentes.

Ao finalizar esta disciplina você será capaz de:

  • Garantir comunicação entre agentes e sistemas com tecnologias diferentes
  • Conectar a IA a dados e ferramentas externas com eficiência
  • Criar servidores MCP como parte do seu ambiente de desenvolvimento
  • Integrar agentes, APIs e sistemas sem limitações de tecnologia
  • Criar aplicações prontas para ecossistemas com múltiplos agentes
┌──────────── A2A ────────────┐ Agente A ◄──────────────────────────────► Agente B (agente ↔ agente) (ADK) (LangGraph) │ MCP │ MCP ▼ ▼ [GitHub] [Postgres] [Figma] [CRM] [Arquivos] (agente → ferramentas/dados)

Protocolos de comunicação × Tool Calling

Tool calling (function calling) é um recurso do modelo/API: você descreve funções no request e o modelo pede para chamá-las. Mas cada aplicação precisa implementar cada integração do zero — N aplicações × M ferramentas = N×M integrações.

Um protocolo padroniza a conversa entre aplicações de IA e provedores de capacidades. Com MCP, quem escreve um servidor (ex.: GitHub) o faz uma vez, e qualquer cliente compatível (Claude, Cursor, Copilot, ADK…) pode usá-lo: N + M em vez de N×M.

Tool callingMCP
NívelFormato de request/response de uma API de LLMProtocolo cliente-servidor (JSON-RPC 2.0)
Onde a ferramenta viveNo código da sua aplicaçãoNum servidor reutilizável (local ou remoto)
DescobertaEstática (você lista no request)Dinâmica (tools/list, notificações de mudança)
Além de ferramentasNãoResources, prompts, sampling, elicitation

MCP usa tool calling por baixo: o cliente converte as tools do servidor em definições de tool para o modelo.

Fundamentos do MCP (Tools, Resources e Prompts)

O Model Context Protocol foi criado pela Anthropic (2024) e hoje é um padrão aberto adotado amplamente. Papéis:

  • Host: a aplicação de IA (Claude Desktop, Claude Code, IDE).
  • Client: o conector dentro do host que mantém uma conexão 1:1 com um servidor.
  • Server: expõe capacidades.
PrimitivaQuem controlaO que éExemplo
ToolsO modelo decide chamarFunções que executam ações ou consultascriar_issue, executar_query
ResourcesA aplicação/usuário escolhe incluirDados para contexto, identificados por URIfile:///docs/api.md, db://schema/orders
PromptsO usuário invocaTemplates de interação reutilizáveis"/revisar-pr", "/analisar-incidente"

Primitivas do lado do cliente: sampling (o servidor pede ao cliente uma geração de LLM), roots (escopo de diretórios) e elicitation (o servidor pede informação ao usuário).

Exemplo: mensagens JSON-RPC (simplificadas)

// cliente → servidor: quais ferramentas você tem?
{"jsonrpc": "2.0", "id": 1, "method": "tools/list"}

// servidor → cliente
{"jsonrpc": "2.0", "id": 1, "result": {"tools": [{
  "name": "buscar_pedido",
  "description": "Busca um pedido pelo ID",
  "inputSchema": {"type": "object", "properties": {"pedido_id": {"type": "string"}}, "required": ["pedido_id"]}
}]}}

// cliente → servidor: o modelo decidiu chamar
{"jsonrpc": "2.0", "id": 2, "method": "tools/call",
 "params": {"name": "buscar_pedido", "arguments": {"pedido_id": "PED-123"}}}

Transportes

  • stdio: servidor local como subprocesso. Simples e seguro para ferramentas na máquina do dev.
  • Streamable HTTP: servidor remoto via HTTP, com streaming opcional (SSE) e autorização OAuth 2.1. Para servidores compartilhados/SaaS.

Servidores MCP e Docker MCP Toolkit

Há milhares de servidores prontos: sistemas de arquivos, Git/GitHub, bancos (Postgres, SQLite), navegadores (Playwright), Slack, Notion, Figma, Sentry, Stripe, documentação (Context7)… Consulte o registro oficial no site do MCP e o Docker MCP Catalog.

O Docker MCP Toolkit (no Docker Desktop) roda servidores como containers isolados, gerencia segredos e expõe tudo por um gateway único ao qual você conecta seus clientes — menos configuração e mais isolamento do que rodar npx de pacotes diretamente na máquina.

Usando MCP direto pela API do Claude

O MCP connector permite que a própria API do Claude se conecte a servidores MCP remotos, sem você implementar um cliente MCP.

Exemplo: MCP connector (Python)

import anthropic
client = anthropic.Anthropic()

resp = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=2000,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{"type": "url", "url": "https://mcp.exemplo.com/mcp", "name": "pedidos"}],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "pedidos"}],   # as duas partes são necessárias
    messages=[{"role": "user", "content": "Qual o status do pedido PED-123?"}],
)

Desenvolvimento de servidores MCP

SDKs oficiais existem para Python, TypeScript, Go, Java, C#, Kotlin e outras. Em Python, o FastMCP (incluído no SDK) transforma funções decoradas em primitivas.

Exemplo: servidor MCP com tools, resources e prompts (Python)

# pip install "mcp[cli]"
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("pedidos")

PEDIDOS = {"PED-123": {"status": "ENVIADO", "itens": ["notebook"], "cliente": "Ana"}}

@mcp.tool()
def buscar_pedido(pedido_id: str) -> dict:
    """Busca status e itens de um pedido pelo ID (formato PED-123)."""
    if pedido_id not in PEDIDOS:
        return {"erro": f"Pedido {pedido_id} não existe. Verifique o formato PED-NNN."}
    return PEDIDOS[pedido_id]

@mcp.resource("pedidos://politica-cancelamento")
def politica() -> str:
    """Política de cancelamento vigente."""
    return "Pedidos PAGOS podem ser cancelados em até 24h. Pedidos ENVIADOS não."

@mcp.prompt()
def analisar_reclamacao(texto: str) -> str:
    """Template para analisar reclamações de clientes."""
    return f"Analise a reclamação, identifique o pedido, consulte-o e proponha uma resposta:\n\n{texto}"

if __name__ == "__main__":
    mcp.run()                                  # stdio (padrão)
    # mcp.run(transport="streamable-http")     # servidor HTTP
# testar com o MCP Inspector (interface para chamar tools/resources/prompts)
mcp dev servidor.py

# registrar no Claude Code
claude mcp add pedidos -- python servidor.py
Boas práticas: descrições excelentes (são o "prompt" da tool); validação de entrada; erros acionáveis; respostas enxutas; paginação; permissões mínimas; logs no stderr (no stdio, o stdout é o canal do protocolo!); autenticação OAuth em servidores remotos.

Deploy e distribuição utilizando Docker

Exemplo: Dockerfile para o servidor

FROM python:3.12-slim
WORKDIR /app
RUN pip install --no-cache-dir "mcp[cli]"
COPY servidor.py .
RUN useradd -m mcp
USER mcp
ENTRYPOINT ["python", "servidor.py"]
docker build -t minhaorg/mcp-pedidos:1.0 .
# uso via stdio por qualquer cliente:
claude mcp add pedidos -- docker run -i --rm minhaorg/mcp-pedidos:1.0

Distribuição: publique a imagem num registry (Docker Hub, GHCR), versione semanticamente, documente variáveis de ambiente e permissões. Para servidores remotos, implante como serviço HTTP (Cloud Run, Kubernetes) atrás de autenticação.

Segurança MCP: servidores podem ser maliciosos (exfiltração, descrições de tool com instruções escondidas — "tool poisoning") ou ser vetor de prompt injection (dados que retornam). Use fontes confiáveis, fixe versões, isole em containers, conceda o mínimo de credenciais e revise as permissões pedidas.

Google A2A (Agent to Agent): fundamentos

O A2A é um protocolo aberto (iniciado pelo Google em 2025, hoje sob a Linux Foundation) para que agentes opacos — construídos com frameworks e fornecedores diferentes, sem expor sua lógica interna, memória ou ferramentas — colaborem como pares. Baseado em padrões web: HTTP, JSON-RPC 2.0 e SSE para streaming (com variantes gRPC/REST nas versões mais novas), além de push notifications via webhook para tarefas longas.

MCPA2A
ConectaAgente → ferramentas e dadosAgente ↔ agente
ContraparteFunções com esquema (previsíveis)Agente autônomo (pode negociar, pedir mais informação, demorar)
Unidade de trabalhoChamada de toolTask com ciclo de vida

Tasks, Messages, Parts, Agent Cards e Artifacts

  • Agent Card: "cartão de visitas" JSON do agente remoto — nome, descrição, URL, capacidades (streaming, push), habilidades (skills), formatos aceitos e esquema de autenticação.
  • Task: unidade de trabalho com ID e estado; pode durar segundos ou dias.
  • Message: um turno de comunicação (role: user ou agent) composto de Parts.
  • Part: pedaço de conteúdo tipado — texto, arquivo ou dados estruturados.
  • Artifact: resultado/produto gerado pela task (relatório, imagem, JSON), também composto de Parts.

Arquitetura e fluxo de comunicação A2A

Cliente A2A (agente orquestrador) Servidor A2A (agente remoto) 1. GET /.well-known/agent.json ──────────────► devolve Agent Card 2. escolhe skill adequada 3. message/send (ou message/stream) ──────────► cria Task (submitted → working) ◄────────── status updates (SSE) / artifacts parciais 4. se input-required: envia nova Message na mesma Task ◄────────── Task completed + Artifacts

Exemplo: requisição JSON-RPC message/send (simplificada)

POST https://agente-viagens.exemplo.com/a2a
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "method": "message/send",
  "params": {
    "message": {
      "role": "user",
      "messageId": "msg-1",
      "parts": [{ "kind": "text", "text": "Reserve hotel em Lisboa de 10 a 14/12, até 150€/noite" }]
    }
  }
}

Tipos de mensagens e partes (text, file, json)

{ "kind": "text", "text": "Resumo da análise..." }

{ "kind": "file", "file": { "name": "contrato.pdf", "mimeType": "application/pdf",
                            "uri": "https://.../contrato.pdf" } }      // ou "bytes" em base64

{ "kind": "data", "data": { "cpf_valido": true, "score": 712 } }        // JSON estruturado

A negociação de formatos acontece pelo Agent Card (defaultInputModes/defaultOutputModes, por exemplo text/plain, application/json), permitindo que agentes se adaptem ao que o outro suporta — inclusive UI e mídia.

Descoberta de agentes (agent.json)

Por convenção, o Agent Card é publicado num caminho bem conhecido do domínio do agente: /.well-known/agent.json (nas versões mais recentes da especificação, /.well-known/agent-card.json). Também é possível descobrir agentes via registros/catálogos corporativos.

Exemplo: Agent Card

{
  "name": "Agente de Viagens",
  "description": "Pesquisa e reserva hotéis e voos.",
  "url": "https://agente-viagens.exemplo.com/a2a",
  "version": "1.2.0",
  "capabilities": { "streaming": true, "pushNotifications": true },
  "defaultInputModes": ["text/plain", "application/json"],
  "defaultOutputModes": ["text/plain", "application/json"],
  "securitySchemes": { "oauth": { "type": "oauth2" } },
  "skills": [
    {
      "id": "reservar-hotel",
      "name": "Reservar hotel",
      "description": "Encontra e reserva hotéis dado destino, datas e orçamento.",
      "tags": ["viagem", "hotel"],
      "examples": ["Hotel em Lisboa de 10 a 14/12 até 150€"]
    }
  ]
}

Composição de agentes de frameworks diferentes

O valor do A2A aparece em ambientes heterogêneos: o agente de RH foi feito com LangGraph por um time, o de finanças com ADK por outro, um fornecedor oferece um agente de viagens próprio. Um orquestrador descobre seus Agent Cards e delega tarefas sem conhecer a implementação de nenhum.

  • O ADK tem suporte nativo para expor agentes via A2A e consumir agentes remotos como subagentes.
  • SDKs oficiais do A2A (Python, JS, Java, Go, .NET) permitem "embrulhar" agentes de qualquer framework (LangGraph, CrewAI, Claude Agent SDK) num servidor A2A.
  • Combine: A2A entre agentes + MCP de cada agente para suas ferramentas.
Pontos de atenção: autenticação entre agentes (OAuth, mTLS), autorização por skill, limites de custo/tempo por task, rastreamento distribuído (propagar trace IDs entre agentes), e tratar a saída de um agente remoto como não confiável (prompt injection entre agentes).

1. Qual primitiva MCP é tipicamente controlada pelo modelo?
Tools são chamadas pelo modelo; resources são escolhidos pela aplicação; prompts são invocados pelo usuário.
2. O agente remoto precisa saber a data de retorno para continuar. Estado da Task A2A?
O cliente responde com nova Message na mesma Task e o trabalho continua.

Escrever no stdout corrompe as mensagens JSON-RPC.
