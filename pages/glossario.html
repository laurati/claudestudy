Glossário

Os termos mais usados nas disciplinas, em ordem alfabética, com link para a disciplina onde são explicados em detalhe.

Termos

A2A (Agent2Agent)
Protocolo aberto para comunicação entre agentes de fornecedores/frameworks diferentes, com Agent Cards, Tasks, Messages e Artifacts. → 09
ADK (Agent Development Kit)
Framework open source do Google para construir, avaliar e implantar agentes. → 08
ADR (Architecture Decision Record)
Registro curto e imutável de uma decisão arquitetural, com contexto e consequências. → 04
Agent Card
Documento JSON que descreve um agente A2A (skills, URL, autenticação), geralmente em /.well-known/agent.json. → 09
Agente
Sistema em que um LLM decide dinamicamente quais ferramentas usar e quais passos seguir até cumprir um objetivo. → 08
AI Gateway
Proxy entre aplicações e provedores de LLM que centraliza roteamento, fallback, custos, limites e logs (ex.: LiteLLM). → 03
Alucinação
Saída plausível porém falsa gerada por um modelo. → 01
Artifact (A2A)
Produto gerado por uma task A2A (documento, JSON, imagem). → 09
Batch API
Processamento assíncrono de muitas requisições com desconto, sem latência garantida. → 02
C4 Model
Modelo de diagramas de arquitetura em quatro níveis: Context, Containers, Components, Code. → 04
Chain of Thought (CoT)
Técnica de pedir raciocínio passo a passo antes da resposta. → 02
CLAUDE.md
Arquivo de memória/instruções do projeto carregado automaticamente pelo Claude Code. → 05
Compaction
Resumo automático do histórico quando a conversa se aproxima do limite de contexto. → 02
Context engineering
Disciplina de decidir todo o conjunto de tokens que o modelo vê a cada passo (instruções, ferramentas, documentos, histórico, memória). → 03
Context window (janela de contexto)
Máximo de tokens que o modelo processa de uma vez (entrada + saída). → 01
Context anxiety
Tendência do agente a apressar a conclusão quando o contexto está quase cheio. → 06
Decoder-only
Arquitetura Transformer que gera texto da esquerda para a direita (Claude, GPT, LLaMA). → 01
DevSecOps
Integração de segurança em todo o ciclo de desenvolvimento e entrega. → 10
Effort
Parâmetro da API do Claude que controla o quanto o modelo raciocina e gasta de tokens. → 01
Embedding
Vetor numérico que representa o significado de um texto; textos parecidos têm vetores próximos. → 01
Error budget
Margem de falha permitida por um SLO (100% − SLO). → 10
Eval (avaliação)
Conjunto de casos + avaliadores para medir a qualidade de um prompt, modelo ou agente. → 02
Few-shot
Incluir exemplos de entrada→saída no prompt. → 02
Fine-tuning
Continuar o treinamento de um modelo com dados próprios. → 01
Guardrails
Verificações ao redor do modelo (entrada, saída, ações) para segurança e qualidade. → 03
Harness
Tudo ao redor do modelo que o torna um agente: loop, ferramentas, contexto, permissões, hooks, verificação. → 06
Hook
Comando executado automaticamente em eventos do agente (antes/depois de uma ferramenta, ao terminar). → 06
HyDE
Hypothetical Document Embeddings: buscar usando o embedding de uma resposta hipotética. → 02
Instabilidade (I)
Métrica de acoplamento: Ce / (Ca + Ce). → 03
LLM
Large Language Model: rede neural treinada para prever o próximo token em grande escala. → 01
LLM-as-judge
Usar um modelo para avaliar saídas de outro segundo uma rubrica. → 02
Main Sequence
Linha A + I = 1 que representa equilíbrio entre abstração e estabilidade de um módulo. → 03
MCP (Model Context Protocol)
Protocolo aberto que conecta aplicações de IA a ferramentas e dados (tools, resources, prompts). → 09
Mermaid
Linguagem de texto que gera diagramas (fluxo, sequência, classes, ER, estados). → 04
OWASP Top 10 LLM
Lista dos 10 principais riscos de segurança em aplicações com LLM. → 03
PRD
Product Requirements Document: problema, objetivos, requisitos e métricas de um produto/feature. → 04
Progressive disclosure
Carregar informações (ex.: skills) em camadas, só quando necessárias. → 07
Prompt caching
Reaproveitamento do processamento de um prefixo repetido do prompt, reduzindo custo e latência. → 02
Prompt injection
Instruções maliciosas inseridas em dados processados pelo modelo. → 03
RAG
Retrieval-Augmented Generation: recuperar trechos relevantes e incluí-los no prompt. → 01
ReAct
Padrão Reasoning + Acting: pensar, agir (ferramenta), observar, em loop. → 02
Runbook / Playbook
Passo a passo para uma tarefa operacional / estratégia para um tipo de situação. → 04
Runner (ADK)
Componente que executa o agente, emite eventos e persiste a sessão. → 08
SDD (Spec-Driven Development)
Desenvolvimento em que a especificação é o artefato principal que guia o agente. → 06
Skill
Pasta com SKILL.md, scripts e referências que o agente carrega sob demanda. → 06
SLI / SLO / SLA
Indicador, objetivo interno e acordo contratual de confiabilidade. → 10
Streaming
Envio dos tokens ao cliente à medida que são gerados. → 03
Structured outputs
Recurso que garante que a resposta siga um esquema JSON. → 07
Subagente
Agente com contexto, instruções e ferramentas próprias, chamado por outro agente. → 06
System prompt
Instruções do desenvolvedor que definem papel, regras e contexto permanente. → 02
Temperature / top-k / top-p
Parâmetros de amostragem do próximo token. → 01
Token
Unidade de texto processada pelo modelo; base de preço e limites. → 01
Tool use (function calling)
Mecanismo em que o modelo pede a execução de funções definidas pela aplicação. → 07
Transformer
Arquitetura de rede neural baseada em self-attention, base dos LLMs. → 01
Worktree (git)
Cópia de trabalho adicional do mesmo repositório, usada para agentes em paralelo. → 06
